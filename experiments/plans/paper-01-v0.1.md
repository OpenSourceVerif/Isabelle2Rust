# 第一篇 workshop 工作方案 v0.1

记录日期：2026-10-23。方案 ID：`paper-01-v0.1`。

状态：讨论版；当前研究方向已确定，执行参数尚未冻结，框架尚未实现。

## 研究目标与边界

先探索从 Isabelle 模型直接生成 Rust 的可行性、行为一致性和生成结果的质量，通过实际实验形成服务于 Isabelle2Rust 的结论。应用案例先使用 AFP，后续扩大范围，再考虑 Solana/SBPF。

当前不以“必须设计一个不同于现有工作的 workflow”为目标，不为凑方法模块或新颖性强行增加机制。最终贡献与论文论断由实验支持，当前不预先承诺性能改善或正确率。

## 已确定的核心方案

1. 第一条实验路线是 LLM 直接从 Isabelle 模型生成 Rust。
2. 框架的核心为两个模块：**生成**与**测试**。上下文准备、反馈修复、测试输入构造等属于内部能力，不另列为顶层研究模块。
3. 测试基线必须包含 Isabelle→OCaml，以及现有 Isabelle2Rust Stage 1、Stage 2。
4. 先接通实际流程再逐步扩大实验；当前不补齐其他论文的全部机制，不开展为了对齐现有工作的实现。
5. 测试提供有限范围内的行为一致性证据，不能表述为 Rust 已继承 Isabelle 证明或已获得完整语义等价证明。当前不做 translation validation（TV）。

## 两个模块的初步职责

### 生成

从选定 Isabelle 定义、必要依赖与任务要求产生 Rust 候选，接受编译诊断和开发测试反例后进行修复。

尚需在首批执行配置中确定：一个任务包含多少函数、提供哪些定义/定理/示例、允许使用的依赖、Rust 接口、生成自由度和调用参数。

### 测试

对齐各实现的合法输入与可观察输出，构建并运行候选，与 OCaml、Stage 1、Stage 2 的结果比较。适用时加入独立数学性质或独立参考算法的检查。收集失败、超时和反馈，并在行为测试后测量性能。

参考实现之间出现差异时，记录为待诊断问题，排查后端、数据适配与输入语义；不能通过多数投票认定正确答案。多个后端仍可能共享前端，因此不能声称它们完全独立。

```text
固定的 Isabelle 模型
  ├─ Isabelle→OCaml ───────── 参考执行
  ├─ Isabelle2Rust Stage 1 ── 参考执行
  ├─ Isabelle2Rust Stage 2 ── 参考执行
  └─ LLM 直接生成 Rust ───── 候选执行
                  │
          对齐输入并比较行为
                  │
            失败信息反馈修复
                  │
             最终评估与记录
```

## 第一轮执行建议（尚未冻结）

以下来自讨论中的建议，不能当成已经实施或已经由用户逐项确定的协议：

- 固定原始 Isabelle 模型，只修改候选 Rust；允许修改 Isabelle 模型的路线留到后续比较。
- 首次生成只提供 Isabelle 任务信息，不提供 Stage 1、Stage 2 或 OCaml 实现；参考实现服务于测试。如果以后开放参考源码，作为不同实验条件单独记录。
- 开发测试用于反馈；最终测试在候选冻结后运行，不能再用其结果修复或选择候选。
- 初期用行为测试驱动修复，性能先作为最终测量，不立即加入性能反馈循环。
- 先用 List-Index 的小任务接通，再考虑其他 AFP 候选。
