## 基线准入与准备中的问题

List-Index 复用第一批保存的 Isabelle 导出源码，并重新构建新 harness、重新检查全部数据。Skew_Heap 从当前环境新导出。

Skew_Heap 的第一次整数专用 Rust 导出虽然成功，随后编译因 BigInt 缺少生成的 Isabelle `Ord` 实例而失败。该失败发生在模型调用之前，原始证据保存在 `preparation-failures/001-missing-integer-order-instance/`。

调整方式：OCaml 使用 Isabelle 内的 `merge_integer` 实例；Rust 导出多态 `Skew_Heap.merge`，在独立 harness 中用 BigInt 载体实现生成的排序 trait。参考算法不作人工改写。此项记为基线准入问题，不计为 LLM 生成失败。

负向检查分别使用“首次位置代替末次位置”和“树合并相等键走错误分支”的人工错误候选；这些不是模型样本。

三套基线最终均通过全部用例；负向检查分别检出 313 和 115 个不一致。两个任务内部的开发/最终输入集合均无重复。

## 性能测量边界

仅对 List-Index 测量 OCaml、Stage 1、Stage 2 及所有通过行为测试的新候选。长度 32/128/512，查找首元素/尾元素/不存在值，共 9 种负载；每次预热 10 次，再计时 500 次调用；每种负载测 7 轮，轮换实现顺序，顺序执行。

计时从预先构造的数组进入调用开始，包含 Rust 输入克隆、参考 Rust 的链表构造、函数执行与 Rust 对应对象销毁；OCaml 包含数组转列表并允许其正常的不可变值共享。排除文件解析、输出、模型调用和编译。这衡量的是给定适配路径的表现，不是孤立函数内核的公平归因实验。

Rust 用单调 `Instant`，OCaml 用 `Unix.gettimeofday`；记录每轮原始时间、调用次数与正确结果，汇总中位数及最小/最大值。最短负载可能只有毫秒量级，跨语言运行时、内存管理及计时器也不同；不把它作为通用性能结论。不按性能挑选候选。

候选预先获得切片接口，参考 Rust 使用生成式链表；接口与表示选择本身影响性能，不能把所有差异归因于模型优化能力。此次不测分配量，也不测 Skew_Heap 性能。

## 性能结果与解释

9 种负载 × 6 个实现（3 个基线加 3 个候选）× 7 轮，共 378 次测量，全部完成。各候选的每调用耗时中位数相对 Stage 2 快约 9.39–15.07 倍；但 **OCaml 在这 9 种负载下都比候选快**。

以长度 512、查询不存在元素为例，各自 7 轮中位数为：

| 实现 | 每次调用耗时 |
| --- | ---: |
| Stage 1 | 25,721.436 μs |
| Stage 2 | 122.749 μs |
| OCaml | 5.512 μs |
| 3 个 LLM 候选 | 8.434–8.513 μs |

这些数字只针对本批约定的数组输入适配路径和本机环境。候选是反向迭代的切片实现，参考 Rust 则经历链表构造和生成代码中的操作；尚未通过消融或 profiling 分离接口、数据结构、克隆和模型选择的贡献。不能写成“LLM 普遍比 Isabelle 后端快”。

## 当前结论与后续问题

1. 直接生成路线已从一个列表函数扩展到一个递归树函数；这两个小任务各三次请求均首次通过，显示当前任务包可运行。
2. 生成多样性较低，不能据此支持“广泛探索了算法或优化空间”；本批也未评估反馈修复的有效性。
3. 性能值得继续分析，但 OCaml 参照改变了结论：相对 Stage 2 的明显改善仍未赶上本批 OCaml 结果。后续应在更复杂任务上检验，并分开测量表示转换、分配与函数本身的成本。
4. Skew_Heap 暴露的整数排序实例准入问题已记录；这说明扩展任务时，仍需先检查参考链路，不能把基础设施失败混入模型失败率。
