ISABELLE 2025 PRINTING SYNTAX REFERENCE (syntax only; choose your own representations):
- A literal underscore in any quoted printing template must be escaped as '_ (apostrophe underscore). Thus a zero-argument type name is "dashu'_int::UBig", NOT "dashu_int::UBig". "Number of arguments mismatch" often means an unescaped underscore in a Rust identifier. Type nat has zero arguments; list has one.
- Rust function call templates: "!crate::Numbers::add'(_, _')" has TWO argument holes. A one-argument call is "!crate::Numbers::inc'(_')". The ! is at the beginning of the string. Do not write (!...). Literal parentheses are escaped; holes themselves are not escaped.
- Prefer ordinary Isabelle surface constants with explicit types to guessed internal names: constant "plus :: nat \<Rightarrow> nat \<Rightarrow> nat"; constant "0 :: nat"; constant "HOL.equal :: nat \<Rightarrow> nat \<Rightarrow> bool". The graph IDs are for traceability, not necessarily valid source syntax. Do not invent Nat.one_nat_inst.one_nat or HOL.Let. Inspect the supplied source catalog if unsure.
- A one-parameter type printing is "Vec<_>"; a product printing is "'(_, _')". Literal zero-argument construction is "Vec::new'(')". Plain Rust support in rust_files is not a printing template and does NOT use these escapes.
